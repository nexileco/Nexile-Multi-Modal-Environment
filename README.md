# Nexile Multi Model Environment 0.21.0
NMME - Nexile Multi Modal Environment VSCode/Cursor Extension
## Install from VSIX

1. Download the `.vsix` file (e.g., `cursor-router-chat-0.21.0.vsix`).
2. In VS Code or Cursor, open the Command Palette (`Ctrl+Shift+P` / `Cmd+Shift+P`) and run **Extensions: Install from VSIX...**.
3. Select the `.vsix` file and confirm. The extension installs and appears in the Activity Bar sidebar.


An independent coding chat extension for Cursor and VS Code. It supports OpenRouter, Groq, Google Gemini, and Mistral, provider-only API-key setup, automatic model routing with sequential failover and focused delegation, custom agent instructions, and workspace tools.

## Run locally

1. Open this folder in Cursor or VS Code.
2. Run `npm install` and `npm run compile`.
3. Press F5 to launch the Extension Development Host.
4. Run **Nexile Multi Model Environment: Open Chat** from the Command Palette. The chat opens as a sidebar view, without creating an editor tab.
5. Open **Settings**, add a provider API key, save the key, and refresh models. Repeat for each provider you want to connect. Keys are stored in SecretStorage.

OpenRouter model lists show only zero-priced models. Gemini discovery is intersected with documented free-tier chat model IDs, checked on 2026-10-14. Groq and Mistral expose chat catalogs without account pricing, so use keys from their free-tier accounts; their account quotas determine which models can run. Billing-enabled accounts follow their provider pricing. Speech, embedding, archived, and explicitly non-chat models are excluded. Saved models absent from the eligible catalog are hidden.

Settings shows provider names with API-key fields, plus agent permissions. Open **Providers** beside the chat input to configure keys. Save the keys and use **Refresh models** to discover connected catalogs. The chat has a model dropdown immediately beside Agent, listing eligible models from all connected providers with an **Auto** option. Provider settings remain API-key rows; tier selectors are not shown. Selecting a model makes it the first coordinator model for subsequent requests while retaining automatic failover and complexity-based specialist routing. The picker is disabled while a request is running. A model name line below the composer controls shows the active coordinator and updates when failover switches it. When idle, it shows the selected or last-used model; before an automatic request starts, it shows Auto.

Each request starts on one model: the model selected in the chat dropdown, or an automatically selected model when **Auto** is chosen. Selection considers task complexity, context size, tool support, and the connected providers. A simple request stays on that model. Other models remain idle until failover or a focused delegated task needs them. If the active model has credit, rate-limit, network, or compatibility issues, the next eligible model continues with its conversation, workspace instructions, completed tool calls and results, and any partial response text. Completed tools are not replayed automatically.

For complex Agent-mode requests, the coordinator responds first and then delegates focused implementation exploration and risk review if it has not already delegated work itself. Specialists receive the task, workspace context, and completed coordinator progress. Their models are selected according to subtask complexity and availability across providers. The coordinator integrates their findings and handles edits and verification. Ask and Plan remain read-only and do not automatically launch specialists. Stop cancels the active coordinator and any specialists. Earlier broadcast settings migrate to this adaptive behavior.

Every request gathers fresh workspace context: a bounded file map, matching code excerpts, the active editor including unsaved changes, and current editor problems. The reply shows which files were included. Matching code has priority when the context window is small. For models that report a context limit, older chat turns are abridged when needed while the current request is retained. The agent can find files by path fragment, read focused line ranges, and search text without case sensitivity by default.

The chat has a history drawer, a Providers button, and a compact composer. The circle beside the composer actions shows estimated context window use for the selected model. Hover over it for estimated tokens and the model limit; a question mark means the provider did not report a context limit. The estimate includes the conversation and, during an agent run, tool calls and results. Use **+** or type **@** to open the context menu. Attach a file, folder overview, selected code, workspace problems, or the last agent terminal result. Folder suggestions come from up to 500 discovered files. The permission selector beside the model switches between Ask, Auto edits, and Run all. Replies show code blocks with Copy actions, plus Copy and Insert at cursor controls. The header shortcut opens Source Control. Chats are saved per workspace. Clicking the history × button directly deletes the chat and its local messages, attached context, and restore checkpoints; it stops an active response before deletion. Deleting the active chat clears its draft, attachments, and agent terminal output. Project files, other chats, API keys, settings, and agents are kept. Older restore checkpoints without a chat owner are also removed on deletion. This does not erase records held by API providers. **Agent** mode can use all workspace tools. **Ask** and **Plan** modes are read-only; Plan asks the model for an implementation plan. **Agents** opens the custom agent manager; its active agent's instructions are used for later requests.

The agent can list files and directories, read files, search literal text, read editor diagnostics, replace a unique text span, create or overwrite files, create directories, move paths, delete files or empty directories, and run terminal commands. In **Settings → Agent permissions**, choose **Ask before workspace changes and commands** (default), **Auto approve workspace changes; ask for commands**, or **Auto approve workspace changes and commands**. With the last option, Agent mode uses file, directory, and terminal tools without confirmation. In Ask mode, proposed file contents open in a diff before an approval prompt. Ask and Plan chat modes remain read-only regardless of this setting. Commands run in Cursor's or VS Code's visible integrated terminal on Windows, Linux, and macOS. When shell integration is active, the agent uses the configured shell. For local file workspaces without shell integration, it switches to a visible captured terminal backed by the operating system's default shell. Both paths return command output and exit status to the agent, so it can inspect failures, edit files, and rerun verification during the same request. Workspaces that are not backed by a local file path require shell integration for captured output. A task stops after 20 tool rounds or a two minute terminal command timeout. The chat shows tool results and offers a **Stop** button. The restore button in the header can undo one of the last eight agent file writes if the file has not changed since that write. Agent tools require a provider model that supports OpenAI compatible tool calls.

Activity appears inline as expandable cards for thinking status, file inspection and edits, terminal commands, and sub-agents. Cards show elapsed time and running, completed, failed, or stopped status. Thinking cards show execution status and provider-supplied reasoning summaries when available. Terminal cards stream captured output and provide **Open terminal**, **Copy command**, and **Stop run** actions. Open terminal allows direct interaction through the editor's terminal. File activities offer **Open file**. Activity records are saved with the chat and removed when that chat is deleted.

The coordinator can also call `delegate_tasks` for focused exploration or review when useful. Subtasks have a six-worker budget per request, with up to three workers per delegation batch and eight tool rounds per worker. Workers inherit workspace rules and can inspect files and diagnostics. They cannot edit files, run terminal commands, or recursively delegate. The coordinator receives their reports and handles implementation, approval prompts, and verification. Deleting the active chat cancels its work and removes its conversation and activity records.

Automatic failover applies to both the coordinator and specialists. Credit exhaustion, authentication failures, model unavailability, rate limits, network errors, malformed or incomplete responses, and 90 seconds without response data trigger a switch. The replacement receives the existing task, conversation, workspace rules, completed tool calls and results, and any partial response text. Interrupted tool-call fragments are discarded; completed tools are not replayed by failover. Existing context compaction applies when the replacement has a smaller context window.

Fallback models come from the combined eligible provider catalogs; models explicitly reporting no tool support are skipped. Gemini tool signatures are preserved on the same model and adapted for cross-model handoffs. Mistral tool-call IDs are normalized consistently for requests and results. Completed tool context is retained across provider changes. The extension tries the current provider first and considers another configured provider after repeated failures. Credit and authentication failures skip the affected provider. Switching providers requires its saved API key. Each agent may try at most five distinct models per request; failure to find an available replacement stops that agent with an error. Stop cancels discovery and model retries. Inline **Switch model** cards record the handoff and its reason. Provider usage limits and account credits are shared by models on the same account.

Provider integration references: [Gemini OpenAI compatibility](https://ai.google.dev/gemini-api/docs/openai), [Gemini free-tier pricing](https://ai.google.dev/gemini-api/docs/pricing), [Gemini history handoffs](https://ai.google.dev/gemini-api/docs/generate-content/thought-signatures), [Mistral API](https://docs.mistral.ai/api), and [Mistral free-mode limits](https://docs.mistral.ai/admin/billing-usage/usage-limits). Free-tier access and quotas depend on the provider account and region.

Root `AGENTS.md`, `.cursorrules`, and `.cursor/rules/*.mdc` files marked `alwaysApply: true` are included in agent requests when present. Attached text files are included in the conversation context, up to five files of 30 KB each.

## Package

Run `npm run compile` and `npm run package`, then use **Extensions: Install from VSIX...** in Cursor or VS Code 1.93 or newer. Cursor rejects extension view containers contributed directly to its right Secondary Side Bar, so Nexile Multi Model Environment uses the supported Activity Bar sidebar. In VS Code, you can move the Nexile Multi Model Environment view to the Secondary Side Bar using the view's context menu.

This extension does not replace Cursor's built in Agent, semantic codebase index, browser integration, MCP, cloud agents, or Tab autocomplete. The workspace tools operate on the first open workspace folder. A chat request has a maximum of twenty tool rounds.
